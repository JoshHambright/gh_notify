# gh_notify v1.3: clear work from the tray

Status: draft for review (2026-10-14). Builds on the v1, v1.1 and v1.2 specs in this folder. Roadmap: `docs/roadmap.md`.

## 0. Goals

1. **Merge** your own ready-to-merge PRs from the popup (GitHub and ADO).
2. **Re-run failed checks** on your CI-failing PRs (GitHub Actions; ADO build policies).
3. **Batch approvals**: approve or reject every waiting deployment approval with one confirm.
4. **Keyboard first**: a global hotkey, keyboard navigation and action keys, and search.

Non-goals:
- merge queue, auto-merge and ADO auto-complete
- admin bypass of branch protection
- re-running checks that don't come from GitHub Actions
- a selection mode with checkboxes on rows
- the macOS port (v2.0)

All names in code, tests, docs and screenshots are placeholders (contoso / fabrikam / acme, alice / bob).

## 1. Shared action rules (unchanged, restated)

Every new action keeps the existing contract in `IItemActions`:

- **Preview** does a live read and returns `ActionPreview(Allowed, Statement, ConfirmLabel, Warning, RefusalReason, Token)`. A refusal shows the reason and offers no confirm button.
- **The confirm button** stays disabled for 600 ms (`ActionText.ConfirmDelay`) after it first appears and again when the popup is re-shown. `ConfirmActionAsync` re-checks this guard.
- **Execute** checks that the token still matches the item, re-reads live state, then writes.
  - A mismatch returns "This action no longer matches what was shown — start again".
  - Changed state returns `Stale: true`, shown as "This changed since you looked — refreshing".
  - HTTP 404, 409 or 422 becomes a stale result (`ActionText.FromHttpError`).
  - A timeout, or a 2xx response with a body that isn't JSON, returns "…it may have been sent. Refresh to check." with `Stale: true`.
- **Logging**: one `Log.Info` line per execute, with the action, item key and outcome. No comment text and no tokens.

`ItemAction` gains `Merge` and `RerunFailed`. `ActionText.DefaultActions`:
- `MyPrReadyToMerge` → `[Merge]`
- `MyPrCiFailing` → `[RerunFailed]`

`ActionText.ButtonLabel`: `Merge` → "Merge…", `RerunFailed` → "Re-run failed…".

`RowStateMachine` labels:

| Action | Sending | Done |
|---|---|---|
| Approve / ApprovePr | Approving… | Approved ✓ |
| Reject | Rejecting… | Rejected ✓ |
| Merge | Merging… | Merged ✓ |
| RerunFailed | Re-running… | Re-run started ✓ |

`HidesOnNextPoll` treats every plain Done label as hide-on-next-poll; a Done row carrying a warning still stays until it is closed.

## 2. Confirm options

Merge needs choices in the confirm panel. `ActionPreview` gains an optional `Options`:

```csharp
public sealed record MergeOptions(IReadOnlyList<MergeMethod> Allowed, MergeMethod Selected, bool CanDeleteBranch, bool DeleteBranch);
public enum MergeMethod { Merge, Squash, Rebase }
```

- `ActionPreview.Options` is `MergeOptions?`; it is null for every other action.
- The panel shows a method picker with only the allowed methods, and a "Delete branch" checkbox when `CanDeleteBranch`.
- The user's choices are passed to `ExecuteAsync` as a new `ActionInput(string? Comment, MergeMethod? Method, bool DeleteBranch)`. This replaces today's `string? comment` parameter, with callers updated.
- Execute refuses with the mismatch error when `Method` is not in `Allowed`.
- Merge has no comment box.
- **Default method:** the config `actions.mergeMethod` if it is set and allowed; otherwise Squash if allowed; otherwise the first allowed method in the order Squash, Merge, Rebase.

## 3. Merge

Offered on `MyPrReadyToMerge` rows only, so only on your own PRs.

### GitHub

**Preview:**
- `GET repos/{repo}/pulls/{n}` and `GET repos/{repo}`.
- It refuses when:
  - `state != open` → "This PR is no longer open"
  - the head sha ≠ `item.HeadSha` → "New commits since you looked — refresh."
  - `mergeable` is null → "GitHub is still checking mergeability — try again in a moment"
  - `mergeable_state` is anything but `clean` or `has_hooks`. The reason is mapped from GitHub's state:

    | `mergeable_state` | Reason |
    |---|---|
    | `blocked` | "Blocked by branch protection" |
    | `behind` | "Behind the base branch" |
    | `dirty` | "Merge conflicts" |
    | `unstable` | "Some checks are not passing" |
    | `draft` | "Draft PR" |
    | anything else | "Not mergeable right now" |

  The refusal panel also offers **Open in browser**, the row's existing open action. There is no admin bypass.
- Allowed methods come from the repo's `allow_merge_commit`, `allow_squash_merge` and `allow_rebase_merge`. If none is allowed, refuse with "No merge method is allowed on this repo".
- `CanDeleteBranch` is true when `head.repo.full_name == base.repo.full_name`. `DeleteBranch` defaults to the repo's `delete_branch_on_merge`, and is false when that is true, because GitHub then deletes the branch itself.
- **Statement:** "Squash and merge PR #12 into main in contoso/api at abc1234". **Confirm label:** "Merge PR #12".

**Execute:**
- `PUT repos/{repo}/pulls/{n}/merge` with `{ sha, merge_method }`. GitHub returns 409 when the head moved, and that becomes a stale result.
- If `DeleteBranch` is set, `DELETE repos/{repo}/git/refs/heads/{headRef}`. If the delete fails, the result is `Ok` with the warning "Merged, but the branch couldn't be deleted: …".

### ADO

**Preview:**
- `GET …/pullRequests/{id}`.
- It refuses when:
  - status ≠ active
  - `lastMergeSourceCommit.commitId` ≠ `item.HeadSha`
  - `mergeStatus` ≠ `succeeded`
  - `isDraft`
  - any policy evaluation for the PR has status `rejected`, or is a blocking `queued`/`running` evaluation
- Allowed strategies come from the target branch's "Require a merge strategy" policy (`GET …/policy/configurations`, type `fa4e907d-c16b-4a4c-9dfa-4916e5d171ab`):
  - `allowNoFastForward` → Merge
  - `allowSquash` → Squash
  - `allowRebase` → Rebase
  - `allowRebaseMerge` is not offered in v1.3.

  With no such policy, all three are allowed.
- `CanDeleteBranch` is always true. `DeleteBranch` defaults to true.

**Execute:**
- `PATCH …/pullRequests/{id}?api-version=7.1` with:

  ```json
  { "status": "completed",
    "lastMergeSourceCommit": { "commitId": "<sha>" },
    "completionOptions": { "mergeStrategy": "noFastForward|squash|rebase", "deleteSourceBranch": true|false } }
  ```

- ADO checks `lastMergeSourceCommit` itself and rejects stale merges with 409. The re-read before writing (sha + `mergeStatus`) stays as defence in depth.

## 4. Re-run failed checks

Offered on `MyPrCiFailing` rows.

### GitHub (Actions only)

**Preview:**
- `GET repos/{repo}/actions/runs?head_sha={sha}&per_page=50`.
- Keep the latest attempt of each workflow (the newest `run_number` per `workflow_id`) whose `conclusion` is `failure`, `timed_out` or `cancelled`.
- If none remain: refuse with "No failed GitHub Actions runs at this commit". If the PR's failing checks come from elsewhere, add "— re-run them in the CI system that reported them".
- **Statement:** "Re-run failed jobs in 2 workflows on #12 (contoso/api): build, e2e". **Confirm label:** "Re-run 2 workflows".
- The token carries the run ids and the sha.

**Execute:**
- Re-check the head sha.
- `POST repos/{repo}/actions/runs/{id}/rerun-failed-jobs` for each run in the token.
- Partial failure → `Ok: true` with a warning naming the runs that failed. All failed → `Ok: false`.

### ADO (build policies)

**Preview:**
- `GET …/policy/evaluations?artifactId=…` (the same query `AdoPullRequests` already uses).
- Keep build-policy evaluations (type `0609b952-1397-4640-95ec-e00a01b2c241`) whose status is `rejected` or whose build result failed.
- If none: refuse with "No failed build policies to re-queue".
- **Statement:** "Re-queue 1 failed build policy on PR #42 (fabrikam/web): CI".

**Execute:**
- Re-check the source commit.
- `PATCH …/policy/evaluations/{evaluationId}?api-version=7.1-preview.1`, the same as the "Re-queue" button on the PR page.
- Partial failure is handled as for GitHub.

The Done message is "Re-run started ✓". The row stays CI-failing until a later poll sees the new results.

## 5. Batch approvals

- **When it appears:** the Approvals section header (`InboxSection.Id == "ApprovalPending"`) shows **Approve all…** and **Reject all…** when it holds 2 or more non-stale rows with an approve action. Muted rows count; hidden and snoozed rows don't, since they aren't in that section.
- **Preview** (`BatchCoordinator` in App, logic in Core `BatchApproval`):
  - Preview every row in parallel, with at most 4 in flight and the existing preview timeout per item.
  - The panel opens under the header and lists one line per item: a checkbox, the repo, the title and the statement. Refused items are unchecked and disabled, showing their reason.
  - One optional shared comment box.
  - **Confirm label:** "Approve 3" or "Reject 3", counting the checked items. Disabled when the count is 0. The 600 ms guard starts once all previews have returned.
- **Execute:**
  - Run checked items **sequentially**, in display order, through the same `ExecuteAsync`, with the shared comment.
  - Each line updates in place: ✓, a stale message, or the error.
  - **Summary line:** "3 approved · 1 changed since you looked · 0 failed".
  - A refresh follows when everything finishes.
- **Single-row interplay:** while a batch is open or running, row-level action buttons in that section are disabled. Opening a row's own confirm is blocked with "Finish the batch first".
- **Cancel** before confirm closes the panel. There is no cancel mid-run; the in-flight item finishes and the remaining items still run, matching single actions, which can't be cancelled once sent.

## 6. Keyboard

### Global hotkey

- **Config:** `hotkey` (string), default `"Win+Shift+G"`. `""` turns it off.
- Grammar: modifiers `Ctrl`, `Alt`, `Shift`, `Win`, joined by `+`, then a key `A`–`Z`, `0`–`9` or `F1`–`F12`.
- Parsed by Core `HotkeyParser.TryParse(string, out Hotkey)`.
- `ConfigValidator` rejects:
  - an unknown modifier or key
  - no modifier, unless the key is F1–F12
  - Shift alone as the only modifier
- **App:** `GlobalHotkey` calls `RegisterHotKey` on a message-only `HwndSource` (`MOD_NOREPEAT`) and toggles the popup (show and focus, or hide). Re-registered on config change.
- If registration fails, the app keeps running and:
  - Settings → General shows "Win+Shift+G is in use by another app — pick another".
  - The log records it once.
  - There is no toast.

### Popup keys

Logic lives in the Core `KeyMap.Resolve(KeyInput, PopupContext) → KeyCommand`. `PopupContext` covers search focus, the selected row's mode, its available actions, and whether a batch panel is open. PopupWindow only translates WPF key events.

| Key | Context | Command |
|---|---|---|
| ↓ / ↑ | list | Move selection (skip section headers; wrap: no) |
| Home / End | list | First / last row |
| Space | list | Expand/collapse the selected row (sections: expand/collapse the section) |
| Enter, O | list, row not confirming | Open the item in the browser |
| A | list | Begin Approve or ApprovePr, whichever the row offers |
| R | list | Begin Reject |
| M | list | Begin Merge |
| C | list | Begin RerunFailed |
| S | list | Open the row's snooze menu |
| Enter | confirm panel open | Confirm (subject to the 600 ms guard; ignored while disabled) |
| Esc | confirm panel open | Cancel the confirm |
| / , Ctrl+F | list | Focus search |
| Esc | search focused, non-empty | Clear search |
| Esc | search focused and empty, or list | Hide the popup |

- An action key that the selected row doesn't offer does nothing; no beep.
- Letters typed into the search box or the comment box are text, never commands. `KeyMap` returns `None` whenever a text box has focus, except for Esc and ↓; ↓ moves from search to the first row.
- **Selection:**
  - Selection is shown with the existing hover style plus a focus border.
  - It is kept across refreshes by item key. If the item disappears, it moves to the row now at the same index, or the last row.
  - Opening the popup selects the first row. Mouse hover doesn't change the selection, but clicking a row selects it.

### Search

- A search box sits at the top of the popup. It is hidden until `/`, Ctrl+F or a click on the 🔍 button in the header.
- Core `InboxFilter.Matches(InboxRow, string query)`:
  - Case-insensitive.
  - Whitespace-separated terms, all of which must match.
  - A term matches the repo display name, the title, the author, or `#<number>` (also a bare number).
- **Applied after presentation:**
  - Sections keep only matching rows; an empty section is dropped.
  - Collapsible sections (Waiting, Snoozed) are expanded while a query is active.
  - Counts show the filtered numbers.
  - The tray icon and the badge are not filtered.
- "No matches" shows when nothing matches.
- **Persistence:** the query lasts until it is cleared or the popup hides; it is cleared on hide.

## 9. Testing

- **Core:**
  - `HotkeyParser` (valid, invalid, case, whitespace)
  - `KeyMap` (every row of the table, including text-box focus and unavailable actions)
  - `InboxFilter` (multi-term, `#12` and `12`, repo alias, no match)
  - `BatchApproval` (eligibility, ≥2 threshold, counts, summary text)
  - `RowStateMachine` labels and HidesOnNextPoll for the new actions
  - default merge method selection
- **GitHub/ADO actions**, with a fake HTTP handler as in today's tests. For merge and re-run:
  - allowed preview: statement, label, options
  - each refusal reason
  - token mismatch
  - method not allowed
  - stale head on execute
  - 409/422 → stale
  - timeout → "may have been sent"
  - partial re-run failure → warning
  - branch-delete failure → warning
  - the exact request body sent
- **App:** the hotkey failure path behind an `IHotkeyRegistrar` seam, and BatchCoordinator sequencing and the summary with a fake `IItemActions`.
- Coverage floor stays at 62; raise it to the measured value minus 1 if that is higher.

## 10. Review focus (risks)

1. Merging the wrong thing:
   - head moved between preview and confirm (sha on PUT / `lastMergeSourceCommit`)
   - a method that isn't allowed
   - deleting a branch from a fork (only same-repo branches)
2. Batch partial failure must never report success for an item that failed, and each item's result must stay on the right line after a refresh mid-batch.
3. Keys leaking into actions while typing in search or comment boxes.
4. Selection jumping to a different item after a refresh, so a later key acts on the wrong row.
5. A hotkey clash or registration failure must never crash the app or block startup.
