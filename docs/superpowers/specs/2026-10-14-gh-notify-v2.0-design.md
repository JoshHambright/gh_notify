# gh_notify v2.0: cross-platform UI (Avalonia), Windows first

Status: approved design (2026-10-14). Builds on v1.0–v1.3. Roadmap: `docs/roadmap.md`. macOS itself ships in v2.1.

## 0. Goals

1. Replace the WPF UI with **Avalonia**, so one UI runs on Windows now and on macOS in v2.1.
2. **No regressions on Windows.** Every v1.3 behaviour, string and safety rule carries over. Users get v2.0 as a normal
   auto-update.
3. Put every OS-specific behaviour behind **platform interfaces**, with the Windows implementations moved out of the UI.
4. **Automated UI tests** with Avalonia.Headless, covering the flows v1.3 could only check by hand: keyboard, search,
   batch, the confirm guard and focus during a refresh.

Non-goals:
- macOS platform code and packaging (v2.1)
- new features
- visual redesign: the layout, colours and copy stay as they are
- code signing

Names in code, tests, docs and screenshots are placeholders only (contoso / fabrikam / acme, alice / bob).

## 1. Project layout

- `GhNotify.UI` never references Windows APIs. CI enforces this with a build of `GhNotify.UI` and its tests on `ubuntu-latest`.
- The package ID, exe name, install root, config path, data dir and env overrides are unchanged.
- Velopack updates v1.3 → v2.0 in place.

## 2. Platform interfaces (in `GhNotify.UI`)

```csharp
public interface INotifier      { void Apply(ToastRequest request); event Action<string /*tag*/, string /*action*/>? Activated; void ClearAll(); }
public interface IHotkeyService { bool TryRegister(Hotkey hotkey, Action onPressed, out string? error); void Unregister(); }
public interface IStartupService{ bool IsEnabled { get; } void SetEnabled(bool enabled); }
public interface ISoundService  { void Play(string soundIdOrPath); }
public interface ISystemTheme   { bool IsDark { get; } event Action? Changed; }
public interface IShell         { void OpenUrl(string httpsUrl); void OpenFolder(string path); void OpenTerminal(string workingDir, string command); }
public sealed record PlatformServices(INotifier Notifier, IHotkeyService Hotkey, IStartupService Startup, ISoundService Sound, ISystemTheme Theme, IShell Shell);
```

- `ToastRequest` and `ToastAction` keep their current shape. If they live in App today, they move to UI.
- Every interface has a fake in `tests/GhNotify.UI.Tests`.
- `IShell.OpenUrl` keeps the `ItemUrl.IsOpenable` check: https only.

## 3. UI port

**Tray**
- `Avalonia.Controls.TrayIcon`, with icons from the existing renderer, ported to Avalonia/Skia drawing: calm, red sweep and count, accent.
- Left click toggles the popup. The menu shows Open, Settings, Check for updates, Restart to update (when one is ready) and Quit, with the same items and order as v1.3.

**Popup**
- A borderless, topmost `Window` anchored above the tray: bottom-right of the work area on Windows, from the screen's working area.
- Hides on deactivate, as today.
- Rows, the ⋯ menus, collapsible sections, confirm panels (merge options, comment box), the batch panel, search box, footer and update link all carry over 1:1.
- Bindings use compiled bindings (`x:DataType`).

**Safety carried over exactly**
- the 600 ms confirm guard, plus re-arm when the popup is shown again
- `ConfirmPointerGuard`: a press must start and end on an enabled confirm button
- no modal dialogs
- the inline Overwrite on a settings conflict

**Settings**
- The same sidebar with six pages, Save/Cancel, validation lists and the hash conflict guard.
- File and folder pickers use Avalonia `StorageProvider`.

**Themes**
- The `Themes/Common.xaml` tokens become an Avalonia `Styles` and `ResourceDictionary` with light and dark variants, following `ISystemTheme` or the configured theme mode.
- The bundled font is kept.

**Rendering on no-op refreshes:** keep the `InboxSections.SameContent` and footer-signature skip, so clicks aren't swallowed (the v1.2 chevron fix).

## 4. Cross-platform fixes in Core and Agents

- `CommandResolver`: on non-Windows, resolve the name on `PATH` with no extensions, and run `.sh` through `/bin/sh`. Windows behaviour is unchanged. Tests run against a fake filesystem or PATH.
- `ClaudeLauncher`: build the "open in terminal" command through `IShell.OpenTerminal` instead of hard-coded PowerShell. The Windows implementation keeps today's PowerShell command line.
- `AppConfig.RepoRoots` default: `C:\dev` on Windows and `~/dev` elsewhere. This is resolved only when a new config is created; existing configs are untouched.

## 5. Testing

- **New `tests/GhNotify.UI.Tests`** (net10.0, Avalonia.Headless.XUnit), using fake platform services and a fake `IItemActions`:
  - **Popup:** sample rows render; chevron and section toggles work on the first click; a no-op refresh keeps the visuals.
  - **Confirm:** Confirm stays disabled for 600 ms; a press-drag onto Confirm doesn't fire; re-arm on re-show.
  - **Merge panel:** the picker lists only allowed methods, and the statement follows the selected method.
  - **Batch:** buttons appear only with ≥2 items; per-item results; the comment box keeps focus and text across a refresh.
  - **Keyboard:** each key in the v1.3 table drives the expected command. Typing in search or comment never triggers an action. The selection survives a refresh.
  - **Search:** filters, "No matches", cleared on hide.
  - **Settings:** load, edit, save, validation errors, the conflict Overwrite path, and the hotkey capture and in-use line.
- **Existing tests:** `GhNotify.App.Tests` move to `GhNotify.UI.Tests` (logic tests) or `GhNotify.Platform.Windows.Tests` (`InstallInfo`, `IcoWriter`, hotkey registrar).
- **Screenshots:** headless rendering replaces `PreviewRenderer` and `build/screenshots.ps1`. It writes the same `docs/images/*.png` set, light and dark.
- **CI:**
  - The existing windows job (gates, coverage floor 62, install/upgrade/uninstall test) stays.
  - The upgrade test adds a **v1.3.x → v2.0** step: install the published v1.3 Setup.exe, then apply the locally packed v2.0, then check that config, state and the Run key survive.
  - A new `ubuntu-latest` job builds `GhNotify.UI` and Core and runs `GhNotify.UI.Tests` headless, proving the UI is platform-neutral.

## 7. Review focus (risks)

1. **Confirm safety regressions:** the 600 ms guard and pointer guard behave differently under Avalonia input routing.
2. **Popup placement and focus:** placement on multiple monitors or mixed DPI, taskbar position (bottom, top or side), and hide-on-deactivate racing a tray click.
3. **Upgrade path:** v1.3 → v2.0 must keep config, state, the Run key and the Start-menu shortcut. The single-instance mutex name must be unchanged.
4. **Toast activation** still routes to the right item after the move to `GhNotify.Platform.Windows`. That includes activation through COM when the app was started by a toast click.
5. **Performance:** popup open time and memory must be no worse than v1.3 (measure both and record them in the PR).
