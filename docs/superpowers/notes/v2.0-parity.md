# v2.0 parity checklist

Exit criteria from the [v2.0 design spec](../specs/2026-10-14-gh-notify-v2.0-design.md) section 6. Tick each box in the PR, against the
Avalonia build, using the v1.3 behaviour described in `README.md` and `docs/*.md` as the reference. Placeholder names only.
Light and dark review frames come from `GHNOTIFY_SCREENSHOTS=<dir> dotnet test tests/GhNotify.UI.Tests --filter Category=Screenshots`
(written to `<dir>/review`).

## 1. What it watches (README)

- [ ] Review requests
- [ ] Deployment and pipeline approvals
- [ ] Your PRs failing CI
- [ ] Your PRs needing a response
- [ ] Your PRs ready to merge
- [ ] Your other open PRs, as the quiet "Waiting on others" list
- [ ] Sections: Waiting and Snoozed collapse and expand; counts correct

## 2. Popup (README, docs/actions.md)

- [ ] Header number equals the tray badge count (excludes muted, snoozed, waiting)
- [ ] Source status line, last-polled text and Refresh (spinner while refreshing)
- [ ] Config error banner
- [ ] Row expand and collapse (chevron and section toggles work on the first click)
- [ ] PR numbers after the repo (`acme/api #57`) and the **PR** detail line when expanded
- [ ] Repo aliases and `maxRepoChars` shortening; full name in tooltip
- [ ] Muted row dimmed with the mute marker; snoozed item at the bottom
- [ ] A no-op refresh keeps the visuals (no flicker, no scroll or selection loss)
- [ ] Popup placement near the tray, hides on deactivate, a tray click right after a hide does not re-open it
- [ ] Empty state

## 3. Actions (docs/actions.md)

- [ ] Approve and reject deployments and pipeline approvals (two-step, live re-check, statement shown)
- [ ] Approve a PR, including the no-pre-review warning
- [ ] Merge: only clean merges, method picker lists only allowed methods, statement follows the method, delete-branch option, pinned to the seen commit
- [ ] `actions.mergeMethod` preference honoured
- [ ] Re-run failed (GitHub Actions) and re-queue failed build policies (Azure DevOps)
- [ ] Refused action shows the reason (for example blocked by branch protection)
- [ ] Failed action shows the message
- [ ] Confirm stays disabled for 600 ms; a press-drag onto Confirm does not fire; re-armed on re-show
- [ ] Batch approve and reject: buttons only with 2 or more items, one confirm, per-item results, comment box keeps focus and text across a refresh

## 4. Keyboard and search (docs/actions.md)

- [ ] Global hotkey toggles the popup (default `Win+Shift+G`), see section 9
- [ ] Down and Up skip section headers; Home and End
- [ ] Space expands or collapses a row or section
- [ ] Enter or O opens the item in the browser
- [ ] A, R, M, C act only where offered
- [ ] S opens the row's snooze menu
- [ ] Enter confirms after the guard; Esc cancels the confirm, otherwise hides the popup
- [ ] `/` or Ctrl+F or the search button opens search; Esc clears search, a second Esc hides
- [ ] Search matches repo, title, author and PR number (`#12` and `12`); "No matches"; Waiting and Snoozed open while searching; header count and tray not filtered; cleared on hide
- [ ] Typing in search or a comment box never triggers an action
- [ ] Opening selects the first row; the selection survives a refresh

## 5. Mute, hide and snooze (docs/notifications.md)

- [ ] Row menu: Snooze (1 hour, 4 hours, Until tomorrow, Next week, Until it changes)
- [ ] Row menu: Mute repo, org, project (1 hour, Until tomorrow, Forever)
- [ ] Footer menu lists active mutes with Unmute; "Nothing muted" when none
- [ ] `filters.mute` patterns: listed dimmed, no toast, sound or auto-agent, not counted
- [ ] `filters.hide` patterns: removed from popup, badge and toasts
- [ ] Pattern syntax (see docs/notifications.md) behaves the same

## 6. Toasts, sounds, off-hours (docs/notifications.md)

- [ ] Toast per new item with the correct title, body and PR number
- [ ] Toast buttons (open, approve or reject where offered) work and open or act correctly
- [ ] Clicking a toast opens the item or the popup
- [ ] Sound per rule: `default`, `none`, each `builtin:` tone (chime, ping, alert, alarm, soft), custom absolute `.wav`
- [ ] One sound per poll, for the most important item
- [ ] Outside `workHours` nothing toasts; `alertOffHours` rules toast and play anyway
- [ ] Work hours days, start and end respected

## 7. Agents (README, docs/workflows.md, docs/security.md)

- [ ] Built-in profiles: review (Pre-review), diagnose-ci (Diagnose), peer-review, pr-shepherd
- [ ] `rules[]` with `agent` auto, button, none and the per-kind defaults
- [ ] `defaultProfiles` overrides; custom prompt and command profiles
- [ ] Run button disabled with a tooltip when `requiresSkill` is not installed
- [ ] Running, queued and cancelled run states shown on the row
- [ ] Finished run shows "Ready" with the one-line summary; open in Claude opens the result
- [ ] `maxConcurrentAgents` and `agentTimeoutMinutes` honoured
- [ ] Hooks fire for ItemAdded, ItemRemoved, ItemChanged, AgentFinished

## 8. Update ready and restart (README)

- [ ] Footer "Update ready - Restart" link appears once an update is downloaded
- [ ] Popup menu: Check for updates; Restart to update after a download
- [ ] Dev build shows "Dev build - updates off"
- [ ] `updates.enabled` and `updates.checkHours`
- [ ] Velopack v1.3 to v2.0 in place upgrade keeps config, state, Run key and Start-menu shortcut (CI step in `build/test-install.ps1`)

## 9. Hotkey and start with Windows

- [ ] Hotkey registers; a hotkey already in use is reported in Settings > General and the app keeps running
- [ ] `hotkey: ""` turns it off
- [ ] Hotkey capture in Settings records modifiers plus key and rejects invalid combinations
- [ ] Start with Windows (Run key written on install, repaired by the install hook, removed on uninstall)

## 10. Tray icon

- [ ] Calm icon when nothing waits
- [ ] Red sweep and count when something waits, attention variant, counts above 9
- [ ] Tooltip text; icon crisp at 16, 20, 24, 32 px
- [ ] Left click toggles the popup; the popup menu offers Settings and Quit
