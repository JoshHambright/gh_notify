# gh_notify v2.2.0

gh_notify now runs on macOS, as a menu-bar app with the same inbox, approvals, agents, mute, hide and snooze as on Windows.

![The popup in dark mode](../images/popup-dark.png)

## Highlights

- **macOS:** install the `.pkg` for Apple Silicon or Intel from the release page. The menu-bar icon turns red when something
  is waiting; its menu opens the popup below it. Notifications work like Windows toasts: click one to open the item.
  [Learn more](../install-macos.md)
- **Updates on both platforms:** macOS builds update themselves from the same GitHub releases as Windows, on their own
  update channel.

## New

- macOS hotkey: **Ctrl+Option+G** by default. `Cmd` and `Option` are accepted in `hotkey` on both platforms.
- macOS **Open at login**, through System Settings › Login Items.
- `display.terminal` (macOS): open terminal actions in Terminal.app, iTerm2 or a command of your own. Settings › Advanced.
- **Install for my user:** when a profile's skill is only in one of your clones' `.claude/skills/`, which agents don't
  load, Settings › Workflows says so and copies it to your user skills folder in one click. The popup's disabled button
  says the same. [Learn more](../workflows.md#installing-skills)

## Fixed

- Skills are found in `$CLAUDE_CONFIG_DIR/skills` when that variable is set, as Claude Code does, instead of always
  `~/.claude/skills`.

## Upgrade notes

Nothing to do on Windows.

On macOS, the app is ad-hoc signed and not notarized yet, so the first launch needs a one-time **Open Anyway** in System
Settings → Privacy & Security. Installing an update may ask for your Mac's admin password, because the installer leaves
gh_notify owned by the system. The Intel build passes CI but hasn't been tested on a real Intel Mac yet.

Known issue: on the Mac it was tested on, the global hotkey registers but macOS never delivers the press, with the default
and with a less common combination. Open the popup from the menu-bar icon for now.
