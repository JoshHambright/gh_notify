# gh_notify v2.0.0

A new foundation, with the same app on top. The UI has been rebuilt on Avalonia, a cross-platform UI framework, so gh_notify can come to macOS next. On Windows everything should look and work as it did in v1.3, plus a proper tray menu.

![The popup in dark mode](../images/popup-dark.png)

## Highlights

- **Right-click menu on the tray icon:** Open, Settings…, What's new, Check for updates, Restart to update (when one is ready) and Quit, like other Windows tray apps. You no longer have to open the popup to quit.
- **What's new after each update:** after an update, the popup footer shows **Updated to vX · What's new** once. It opens that version's release notes (this page). The tray menu's **What's new** item always opens them.
- **Built for macOS next:** the UI no longer depends on Windows. Toasts, the global hotkey, start with Windows, sounds and theme detection now sit behind small platform services that a macOS version can provide. See [the roadmap](../roadmap.md#v21-macos).

## Changed

- The popup, ⋯ menus, confirm panels, batch approvals, search and the Settings window are drawn by Avalonia instead of WPF. The layout, colours, wording and keyboard shortcuts are unchanged. If something looks or behaves differently from v1.3, please [open an issue](https://github.com/JoshHambright/gh_notify/issues).
- The safety rules carry over exactly:
  - Confirm stays disabled for 600 ms.
  - A press dragged onto Confirm doesn't count.
  - Every action re-checks live before it runs.

## Fixed

- Clicking a toast when gh_notify wasn't running now starts the app and opens the item.
- `/` opens search on any keyboard layout.
- After Ctrl+F, the next `/` you type in the search box is no longer swallowed.

## Upgrade notes

Nothing to do. v2.0.0 updates in place from v1.3. Your settings (`%AppData%\GhNotify\config.json`), mutes and snoozes, and start with Windows are kept. CI installs the published v1.3.0, upgrades it to this version, and checks all of them.
